## Por qué una sola sesión de Claude Code ya no lo cuenta todo

Muchos desarrolladores pagan ya más de un plan de IA para programar: un plan personal de Claude, una licencia del trabajo, un plan de ChatGPT para Codex y quizá una cuenta extra para proyectos propios. Cada uno mide el uso con sus propios límites y se reinicia a su propio ritmo. La CLI te muestra la sesión con la que has entrado, de una en una, así que la pregunta que importa —*¿qué cuenta debería usar ahora mismo?*— no tiene respuesta en ningún sitio.

No saberlo sale caro sin hacer ruido. Un límite semanal que has pagado se reinicia sin usar mientras agotas el límite de 5 horas de otra cuenta y te quedas parado a mitad de una tarea.

## Qué debe mostrar un control de uso de Claude Code

Un buen control responde cuatro preguntas para cada cuenta, no solo para la actual:

1. **Cuánto queda** en cada límite: el de 5 horas y el semanal.
2. **Cuándo se reinicia** cada uno, para saber qué caduca antes.
3. **Qué cuenta usar ahora**, teniendo en cuenta las dos cosas.
4. **Cuánto vale el uso**, para saber si un plan compensa.

## Cómo sigue Tokenaitor tu uso

Tokenaitor es una app de escritorio. Encuentra las sesiones de Claude Code y Codex que ya tienes en tu ordenador y, para cada una, pide sus límites al proveedor: al endpoint de uso de Claude Code y al de uso de ChatGPT para Codex, y si no responde, a los límites que Codex escribe en sus registros de sesión. Ante cada proveedor se identifica con su propio nombre, `subtrack-desktop`.

Los tokens se cuentan en las propias transcripciones de las CLI, por modelo y por día, y se valoran a los precios de la API de cada proveedor. Así la [guía de precios](/es/claude-code-pricing/) puede comparar el precio de un plan con lo que costaría el mismo uso en la API.

<Callout>
  Tokenaitor nunca renueva el token de un proveedor. Los tokens de renovación de Claude Code rotan, así que una renovación desde otra app cerraría la sesión de la CLI. Tokenaitor solo lee.
</Callout>

## La cuenta que toca usar

La cola ordena las cuentas por **margen por hora antes de su reinicio**: una cuenta con el 40 % libre que se reinicia en dos horas va antes que otra con el 70 % que se reinicia en cinco días. Tokenaitor pone esa cuenta arriba de la lista y en la barra de menús.

Cuando decides cambiar, marcar una cuenta como en uso escribe un pequeño archivo de referencia. Un fragmento de shell opcional hace que `claude` y `codex` en tu terminal lo sigan, y puedes quitarlo cuando quieras.

## Añadir más cuentas

**Añadir cuenta** inicia una nueva sesión en su propia carpeta con la CLI del proveedor (`claude auth login`, `codex login`), así una segunda sesión nunca cierra la primera. Usa las cuentas que tengas según las condiciones de cada proveedor: tu plan personal y el del trabajo, o planes que pagas tú.

## Renovaciones y lo que caducó sin usar

Los proveedores no informan del día de cobro, así que lo indicas una vez por cuenta. Tokenaitor muestra entonces un calendario de renovaciones y, en el resumen, cuánto límite pagado caducó sin usar el último mes.
