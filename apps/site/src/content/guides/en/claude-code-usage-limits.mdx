## Two windows, two clocks

Claude Code and Codex both meter usage in **windows**, not a monthly pool:

- The **5-hour session window** caps how much you can do in a burst. It starts with your usage and resets five hours later.
- The **weekly window** caps the week as a whole and resets on its own schedule.

A plan can run out of either one. You can hit the 5-hour limit with most of the week left, or run out of the week with the session window full.

## Which plans meter which window

| Plan | 5-hour window | Weekly window |
| --- | --- | --- |
| Claude Pro, Max, Team | Yes | Yes |
| Claude Ultra | No | Yes |
| ChatGPT Go, Plus, Business | Yes | Yes |
| ChatGPT Pro ($100, $200, $500) | No | Yes |

Plan prices are in the [Claude Code pricing](/claude-code-pricing/) and [Codex pricing](/codex-pricing/) guides.

## What happens at the limit

When a window runs out, the agent stops accepting work on that account until the window resets. The CLI tells you when that will be, but only for the account you are using.

## Use the window that expires first

If you hold more than one account, the efficient order is not "the one with most left". It is the one with the most headroom **per hour before it resets**: a weekly window with 40% left that resets tomorrow is worth more right now than one with 80% left and six days to go, because the first will be lost if you don't use it.

<Callout>
  That ranking is Subtrack's queue. It puts the account to use next at the top of the list and in your menu bar, across Claude Code and Codex, and checks every ten minutes.
</Callout>

## Avoid hitting the 5-hour limit mid-task

- Start long tasks on an account whose session window has just reset.
- Keep a second account for when the first runs low, and switch before it does.
- Check what is left before a long agent run, not after it stops.
