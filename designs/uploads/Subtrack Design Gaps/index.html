What the app shows that the design never drew

The eight designed screens and the sign-in flow are built to the export. Everything below is what Subtrack also has to show, and where today's version is either the Flama starter's styling or something I made up. Screenshots are the real app, dark theme, 1440px unless marked.

Needs a design

No screen in the export covers these. Ordered by how often someone will see them.

Biggest gap

First run: an account with nothing synced yet

/dashboard /accounts /people /usage /tokenmaxx /renewals
  • Everyone starts here: the account exists, but the desktop app hasn't found any logins yet.
  • Today each page renders its full layout with zeros: "$0", "0 accounts", an empty table that reads "0–0 of 0", a flat chart.
  • Nothing tells the person what to do next: install the desktop app, sign in there, wait for the first sync.
NeededOne first-run state (or one per page) that points to the desktop app, plus how a page looks with one account but no usage yet.
Starter screen

My profile

/profile · Profile, Password, Sessions, Preferences
  • This is the Flama starter's page, restyled only by the shared tokens. It's the screen in your screenshot.
  • The copy is written for a team product: "how teammates see you across the workspace", "Managed by your workspace — contact an admin".
  • Preferences offers table density, a weekly digest and product update emails. Subtrack sends no email and has no dense tables.
  • Phone and job title don't mean anything for a personal app.
NeededWhat a personal account page holds (name, email, password, two-factor, devices, language, theme?), and whether it should merge into Settings instead.
Starter screen

Two-factor: setting it up, and the code at sign-in

Profile → Password → Two-factor · /login after a correct password
  • Setup is three steps in the starter's gradient-topped dialog: confirm the password, scan the QR code and enter a code, then save the backup codes.
  • The sign-in step asks for the 6-digit code, with "use a backup code" and "trust this device". It isn't captured here, but it has the same starter look.
NeededThe setup steps, the backup-codes step, and the code screen in the sign-in layout you already designed.
Invented

Set a new password

/reset-password?token=… (the link in the reset email)
  • The design has "Reset your password" and "Check your email", but not the page the email link opens.
  • Today it uses the design's auth frame with the starter's password checklist under the fields.
NeededThe new-password screen, its checklist, an expired-link state, and "password changed".
Invented

Settings → This computer

/settings, in the desktop app and in a browser
  • The design's Settings has Workspace and Notifications. Subtrack's real settings are about the machine, so I made up this card.
  • In the desktop app it shows: how many logins it found and when it last synced; Add Claude Code, Add Codex and Refresh; the terminal integration, printing the raw shell snippet; and one toggle per Claude Code login for the live limits feed.
  • In a browser it says to open the desktop app.
  • The Security card below it reuses the profile's session rows.
NeededHow the machine settings read, including the "installed / not installed" states and a calmer way to show the shell snippet.
Invented

Add account

Subscriptions → Add account (desktop app only)
  • The design's "Add subscription" opens a form. Subtrack's adds a login instead: a menu (Claude Code, Codex), then the provider's own sign-in in a terminal window.
  • There is no screen for "waiting for you to sign in", success, or "that account is already tracked".
NeededThe add flow: pick a provider, the waiting state while its sign-in runs, then done or failed.
Starter screen

Search (⌘K)

The sidebar's Search field
  • The design draws the field, not what opens. Today the starter's palette lists the six pages.
  • Searching accounts by email or plan would make it useful.
NeededThe palette, and what it can find.
Missing

Page not found, and when something breaks

Any unknown URL · a crashed page · the API unreachable
  • An unknown URL prints the router's bare "Not Found" in the corner.
  • A crash shows the starter's error screen, and an unreachable API shows a red alert inside the page.
NeededNot found, something went wrong, and "can't reach Subtrack" (offline).
Invented

Phone width

Every page in a narrow window
  • The design is desktop-only. On a narrow window the sidebar becomes a top bar with a menu button, and the pages stack.
  • The desktop app's window can be made narrow too.
NeededWhether narrow widths matter. If so, the bar and one page as a pattern.
Starter screen

Public pages

/about /privacy /terms (/ goes straight to sign-in)
  • These are still the starter's marketing for a team workspace ("One workspace for your team, with the right access for everyone"), in its own light layout.
  • Privacy and terms will need real text either way: what the desktop app reads, and what reaches the server.
NeededA product call first: keep a public site, or only privacy and terms? Then their design.

Adapted from the design: please check

The design was drawn for a team. These screens keep its layout but change what it means for one person with several logins.

Adapted

People

/people
  • A "person" here is an email a provider knows a login by, and their tools are the plans signed in under it.
  • "Idle seats" became idle plans: a plan that used under 5% of its week.
  • The design's Add person, Edit tools and Remove person have no meaning for one person, so they're not shown. Each row opens to its plans with an Edit button.
CheckIs "People" the right word and the right page for one person's logins?
Adapted

Renewals

/renewals · the account editor's new field
  • Claude and Codex never say when a plan bills, so each account got a "Renews on day of month" field the person fills in.
  • Paid plans without a day are listed under a "No renewal day yet" block I added below "Next 30 days", each with Set day.
  • Trials don't exist for these plans, so the trial chips are gone.
CheckWhere to ask for the billing day, and how plans without one should look.
Adapted

One provider's accounts

/accounts/claude-code · /accounts/codex
  • Built from the design's "Claude Max accounts" screen, which shows one plan shared by people.
  • Here it shows one provider's logins: the pick for next, a card per login with its week, session, terminal switch and Edit/Remove, then suggested moves.
CheckWhether this page earns its place next to Subscriptions and Tokenmaxx.
